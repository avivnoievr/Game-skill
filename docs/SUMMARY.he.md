# Game Studio 3D: סיכום מלא של מה שנבנה

> **בשורה אחת:** פלאגין ל-Claude Code שמשנה את **תהליך העבודה** של קלוד על משחקי תלת-ממד. עכשיו הוא קודם מחליט על כיוון אמנותי במספרים, בונה מודלים בשיטה שעובדת ובודק אותם בסקריפטים, ומסתכל על כל מה שהוא יוצר. מבקרים עצמאיים שופטים את העבודה מול ספים קשיחים, והוא לא אומר "גמור" בלי ראיות.

כולו, וקובצי העומק נטענים רק כשהמשימה צריכה אותם. זה חוסך הקשר (context) וכסף. ההנחיות הקריטיות נמצאות בראש
הקובץ בכוונה, כי אחרי דחיסת שיחה נשמרות רק תחילת ההוראות.

מחולל המשחקים האוטונומי המצליח ביותר (godogen) ויתר על הצנרת מרובת השלבים שלו. מה שכן עובד הוא תפקידים
שמביאים משהו אמיתי: הקשר נקי לעבודה רועשת, שיפוט עצמאי, ומקביליות אמיתית. שמות תפקידים בלבד לא מוסיפים
יכולת, ומערכות מרובות סוכנים צורכות פי כמה טוקנים.

## 4. בקרת איכות לעומק (מה שביקשת שיהיה הכי חשוב)

### העיקרון
המחקר (סוכן 4) הראה שני דברים. ראשית, **"תבדוק את עצמך" לא עובד**: מודל שבודק את ההיגיון של עצמו בלי מידע
חיצוני לא משתפר באופן אמין, ולפעמים אפילו מחמיר. שנית, **ראיות חיצוניות כן עובדות**: תמונות, מדדים, בדיקות
ושגיאות. Anthropic עצמה מצאה שקלוד ששופט את העבודה של עצמו "משבח בביטחון גם עבודה בינונית בעליל", וכבודק QA
הוא "מזהה בעיות אמיתיות ואז משכנע את עצמו שהן לא חשובות". לכן כל השערים בנויים מראיות חיצוניות, והשיפוט
נעשה בידי מבקר נפרד.

### 8 השערים
| שער | מתי | תנאי |
|---|---|---|
| G0 | לפני הפיצ'ר הראשון | המשחק עולה, יש מצב QA, ו-`verify.sh` רץ |

### מדדי תמונה אובייקטיביים (נגד מבקר "מנומס")
לכל צילום מסך מחושבים ניגודיות, מגוון צבעים, שטח הצבע הדומיננטי, צפיפות קצוות וחשיפת יתר. סצנה שטוחה,
ריקה או שטופה בערפל מסומנת אוטומטית, והמבקר חייב להתייחס לכל סימון בכתב. בבדיקה, סצנת המבחן "התכנותית" שלי
סומנה כשטוחה ובעלת ניגודיות נמוכה, ובצדק.

## 5. "הנזיפה": איך גרמנו לו להיות רציני וביקורתי, ולמה לא בצעקות

ביקשת הנחיות שנוזפות בו ודורשות עבודה טובה. **בכנות:** המחקר (סוכן 4, מתוך ההנחיות הרשמיות של Anthropic
למודלים החדשים) מצא שמשפטים כמו "CRITICAL: YOU MUST!!!", איומים וצעקות **לא עובדים במודלים החדשים, ואפילו
מזיקים**. הם גורמים לתגובת-יתר ולחוסר יציבות. גם "תבדוק שוב את העבודה שלך" מוסיף עלות בלי איכות.

**מה כן עובד, ומה בנינו:**
1. **סטנדרט מוצהר עם הסיבה:** בראש ה-SKILL.md כתוב במפורש שהבנייה הקודמת נראתה עשויה ב-AI, ש"משחק שרץ אבל
   נראה כמו programmer art נכשל בדרישה העיקרית שלו", ושבינוני נחשב כישלון. זו ה"נזיפה", בצורה שעובדת.

## 7. MCP וכלים חיצוניים: מה כדאי לך

**הממצא הכי חשוב (סוכן 5 בדק בפועל):** בלנדר דרך סקריפטים "ללא ממשק" (headless) **אמין יותר מכל MCP**.
ה-MCP הפופולרי ביותר לבלנדר (כ-30 אלף כוכבים) בכלל לא מוכן לעלות בלי ממשק גרפי, ויש לו באג פתוח של
"תקיעות" בבלנדר 5.1 ומעלה. לכן ה-MCP הוא תוספת לשולחן העבודה, לא תנאי.

| דרגה | מה |
|---|---|
| **חיוני** | Blender ללא ממשק (או `pip install bpy`), glTF-Transform עם הוולידטור של Khronos, Playwright, וה-CLI של המנוע שלך |
| **מומלץ** | **Blender Lab MCP הרשמי** (מפתחי Blender, דורש 5.1+) לעבודה חיה על המחשב שלך; **Chrome DevTools MCP** למדידת ביצועים במשחקי ווב; MCP של המנוע (godot-ai או unity-mcp); Poly Haven (HDRI וטקסטורות CC0) |
| **אופציונלי (בתשלום)** | Meshy (דמויות אנושיות ושלד), Tripo (שלדים ליצורים), ו-**Higgsfield שכבר מחובר אצלך**: `generate_3d` הופך תמונה למודל, ועולה קרדיטים. ה-Blender המתארח שלו לא יכול לייבא קבצים שלך |

## 8. התקנה ושימוש, צעד אחר צעד

**דרך 1, פלאגין** (Claude Code על המחשב שלך):
```
/plugin marketplace add avivnoievr/Game-skill#claude/3d-game-dev-skills-system-13c0pn
/plugin install game-studio@game-skill
```
(אחרי מיזוג הענף ל-main, מספיק `avivnoievr/Game-skill` בלי ה-`#...`.)

**דרך 2, לתוך הריפו של המשחק.** זו הדרך המומלצת אם אתה עובד ב-Claude Code בענן, כי סשנים בענן **לא טוענים
פלאגינים** מה"חנות":
```bash
git clone https://github.com/avivnoievr/Game-skill
bash Game-skill/install.sh /path/to/your-game     # ב-Windows: .\install.ps1 -Target C:\path\to\game
# ואז commit לתיקייה .claude בריפו של המשחק
```

**דרך 3, למשתמש שלך בלבד:** `bash install.sh --user`

**ואז:** פותחים סשן חדש בפרויקט המשחק ומדביקים את **פרומפט א'** מ-`PROMPT.md` (למשחק קיים). הוא יתחיל בבדיקה,
יראה לך את הבעיות המרכזיות עם ראיות, ויציע 2–3 כיוונים אמנותיים לבחירה.

**דרישות בפרויקט המשחק:** `npm i -D playwright gltf-validator` (למשחקי ווב), ו-Blender או `pip install bpy`
(צריך Python 3.13).

## 9. מה נבדק בפועל ומה לא

**נבדק בהרצה אמיתית בסביבה הזאת (Linux בלי GPU):**
- `inspect_model.py` על Blender 5.2.2: תפס נורמלים הפוכים, קנה מידה שלילי, חומר חסר, יחידות שגויות, חריגת
  תקציב וחלק צף. העביר מודל תקין. נבדק גם על מודלי הדוגמה הרשמיים של Khronos.
- `render_views.py`: שלושה מנועי רינדור, כל הזוויות, צללית, רשת, דמות קנה מידה, ופס תנוחות של אנימציית Run.
  וידאתי שהתנוחות שונות.
- `capture.mjs`: צילום WebGL, לכידת שגיאות, ה-hook של מצב ה-QA, תנועה דטרמיניסטית עם מקש לחוץ (4 מ'/ש'
  בדיוק), גווני אפור ומדדים. בנוסף נבדקו 6 תרחישים: ready מאוחר (ממתין), משחק שלעולם לא מוכן (נכשל), מסך ריק
  (נכשל), חריגה מתקציב (נכשל), דליפת זיכרון (נתפסה: 6→24 גיאומטריות), ומשחק תקין (עובר).
- `clip_report.py`: הקליפים של ה-Fox עוברים, וקליפ עם קפיצה מכוונת בנקודת הלולאה נכשל.
- `image_metrics.py`: רץ על צילומים מ-Godot, מהווב ומ-Blender. סצנת ברירת המחדל האפורה של Godot סומנה ב-4 דגלים.
- `check_gltf.mjs` ו-`verify.sh` על פרויקט Vite + TypeScript + three.js r186 אמיתי, גם בכישלון וגם בהצלחה.
- קוד three.js מקובצי העזר עבר בדיקת טיפוסים קפדנית מול three r186.
- קוד Godot מקובצי העזר רץ ב-Godot 4.7.2 (אחרי אימות checksum של ההורדה הרשמית).
- `claude plugin validate --strict` עבר לפלאגין ול-marketplace, וגם בדיקת הסקילים של skill-creator.
- **בודק עצמאי** (סוכן נפרד, קריאה בלבד) עבר על כל הפלאגין ומצא **7 בעיות חוסמות ו-15 אופציונליות**, ביניהן באג
  אמיתי: `capture.mjs` לא באמת המתין שהמשחק יהיה מוכן, ולכן צילם סצנות טעונות למחצה. הבדיקות שלי פספסו את זה
  כי דף הבדיקה שלי סימן ready מיד. **כל הממצאים תוקנו ונבדקו מחדש בשני הכיוונים** (מה שצריך להיכשל נכשל, ומה
  שצריך לעבור עובר), והם בקומיט נפרד. זו בדיוק הסיבה שהסקיל מחייב מבקר נפרד: גם אני, כבונה, פספסתי.

**לא נבדק:** קוד Unity (אין Unity בסביבה), `install.ps1` (אין PowerShell), שירותי היצירה בתשלום ושרתי MCP
(תועדו לפי התיעוד שלהם בלבד), ובעיקר **ההשפעה על איכות המשחק שלך בפועל**. את זה אפשר למדוד רק על המשחק עצמו.
