# פיתוח במאגר הישן, הפצה במאגר החדש

מקור הפיתוח נשאר **avivnoievr/Game-skill**. מאגר ההפצה המיועד הוא
**avivnoievr/game-studio-3d**, עם ענף `main`. כל עדכון לסקיל, לסוכנים, לטסטים,
להוראות ההתקנה ולמסמכי ההפצה נעשה קודם במאגר הפיתוח.

המאגר החדש יקבל גרסאות שנבחרו ונבדקו; אין סנכרון אוטומטי בין המאגרים.
משוב יכול להגיע דרך Issues במאגר ההפצה, והטיפול בו מתבצע במאגר הפיתוח.

## הכנת מועמד להפצה

לאחר שסיימנו שינוי ובדיקות שמתאימות לו, בוחרים SHA מלא של קומיט שמור.
מספר הגרסה חייב להתאים למטא־דאטה של הפלאגין באותו קומיט.

```bash
python3 tools/prepare_distribution.py --ref FULL_SOURCE_SHA --version 1.1.1 --output ../game-studio-3d-candidate
```

הסקריפט קורא את הקומיט עצמו באמצעות `git archive`, ולא את קבצי העבודה שאולי
כבר השתנו. הוא מכין תיקייה חדשה עם הסקיל, הסוכנים, הטסטים, התיעוד והרישיונות;
העמוד הראשי וטופסי המשוב נוצרים מהתבניות ב־`distribution/`.
`RELEASE.json` מתעד את מקור הגרסה, ה־SHA וחתימות הקבצים. ברירת המחדל היא
**candidate**, ללא אישור. קישורי ההתקנה בתבנית מצביעים לתג העתידי, ולכן אינם
פעילים עד פרסום הגרסה במאגר החדש.

## בדיקה ואישור שלך

אתה בודק את המועמד על המשימה שרלוונטית לך. אנחנו מתעדים את ה־SHA המדויק,
מה נבדק, מה ראית בפועל ואילו מגבלות נשארו. רק אחרי אישור מפורש שלך לאותו
קומיט מכינים חבילה מאושרת עם רשומת אישור:

```json
{
  "approved": true,
  "approved_by": "OWNER_NAME",
  "approved_at": "YYYY-MM-DD",
  "source_commit": "FULL_SOURCE_SHA",
  "version": "1.1.1",
  "checks": ["הבדיקות שבאמת בוצעו"],
  "observed_result": "מה נצפה בפועל",
  "limitations": ["מגבלות ידועות, או אמירה מפורשת שלא נמצאו במסגרת הבדיקה"]
}
```

```bash
python3 tools/prepare_distribution.py --ref FULL_SOURCE_SHA --version 1.1.1 --approval-record ../approval.json --output ../game-studio-3d-approved
```

הדוגמה אינה אישור שבוצע. הסקריפט בודק שקיימת רשומה תואמת, אבל אינו יכול
לדעת בעצמו מי אישר; מקור האישור חייב להיות ההחלטה האמיתית שלך.
SHA או מספר גרסה שונים אינם מכוסים באישור הקודם.

## פרסום והשוואה

אחרי אישור בודקים את חתימות החבילה וההתקנה, מעלים את התוכן למאגר ההפצה,
ויוצרים תג חדש `v1.1.1` והערות גרסה. אין להזיז תג קיים או לדרוס היסטוריה.
כל השוואה נשענת על קומיט או תג קבוע, כדי שהבסיס לא ישתנה בזמן הבדיקה.
גם הבדיקות וגם תיעוד המגבלות נשארים נגישים.

מאגר ההפצה מתחיל עם היסטוריה חדשה משלו. מעתיקים לתוכו את הקבצים המוכנים,
ולא דוחפים או משכפלים את היסטוריית הקומיטים של מאגר הפיתוח. קישור המקור,
הרישיונות והקרדיטים נשמרים בחבילה; קישורי סשן בהודעות קומיט ישנות נשארים
רק בהיסטוריה הישנה. הטסטים של כלי הכנת ההפצה עצמו נשארים במאגר הפיתוח,
וכל בדיקות זמן הריצה של הסקיל מועתקות לחבילה.

הסקריפט אינו יוצר מאגר, אינו מעלה קבצים ל־GitHub ואינו מפיץ דבר אוטומטית.
שני המאגרים אינם שני ענפי פיתוח עצמאיים: רק הישן הוא מקור השינויים.

גרסה 1.1.1 כוללת את תוספת שיקול הדעת העיצובי ואת אריזת ההפצה; הבדיקות
הקודמות של 1.1.0 עדיין מתועדות כבדיקות היסטוריות. הכנת החבילה אינה מוכיחה
איכות עיצוב של קלוד במשחק אמיתי ואינה מחליפה את הבדיקה שלך.
